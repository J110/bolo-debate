# Bolo Debate - Deployment Guide

This guide walks you through deploying Bolo Debate to production using:
- **Render** - Backend API, PostgreSQL, Redis
- **Fly.io** - LiveKit (self-hosted real-time audio)
- **Vercel** - Flutter Web frontend

## Prerequisites

- [Render account](https://render.com) (free tier available)
- [Fly.io account](https://fly.io) (free tier available)
- [Vercel account](https://vercel.com) (free tier available)
- Fly CLI installed: `brew install flyctl` or `curl -L https://fly.io/install.sh | sh`

## Step 2: Deploy Backend on Render

### 2.1 Push code to GitHub
```bash
cd ~/bolo-debate

# Initialize git repo (if not already)
git init
git add .
git commit -m "Initial commit"

# Create GitHub repo and push
# Go to github.com/new and create 'bolo-debate' repo
git remote add origin https://github.com/YOUR_USERNAME/bolo-debate.git
git branch -M main
git push -u origin main
```

### 2.2 Deploy via Render Dashboard

1. Go to [Render Dashboard](https://dashboard.render.com)
2. Click **"New +"** → **"Blueprint"**
3. Connect your GitHub repo
4. Select the `bolo-debate` repository
5. Render will detect `backend/render.yaml` and create:
   - Web Service (bolo-debate-api)
   - PostgreSQL Database (bolo-debate-db)
   - Redis (bolo-debate-redis)

### 2.3 Set Environment Variables

After blueprint deployment, go to your web service and add these env vars:

| Variable | Value |
|----------|-------|
| `OPENAI_API_KEY` | `your-openai-api-key` |
| `LIVEKIT_API_KEY` | `your-livekit-api-key` |
| `LIVEKIT_API_SECRET` | `your-livekit-api-secret` |
| `LIVEKIT_URL` | `wss://your-project.livekit.cloud` |

### 2.4 Run Database Migrations

After deployment, open the **Shell** tab in Render and run:
```bash
npx prisma db push
npx tsx prisma/seed.ts
```

### 2.5 Note your API URL
Your backend will be available at:
```
https://bolo-debate-api.onrender.com
```

## Step 3: Deploy Frontend on Vercel

### 3.1 Build Flutter Web

```bash
cd ~/bolo-debate/apps/flutter_app

# Build with production URLs
flutter build web --release \
  --dart-define=API_BASE_URL=https://bolo-debate-api.onrender.com \
  --dart-define=LIVEKIT_URL=wss://bolo-debate-chldbsx4.livekit.cloud
```

### 3.2 Deploy to Vercel

```bash
# Install Vercel CLI (if not installed)
npm i -g vercel

# Deploy
cd ~/bolo-debate/apps/flutter_app
vercel --prod
```

When prompted:
- Set up and deploy: **Y**
- Link to existing project: **N**
- Project name: **bolo-debate-web**
- Directory: **./build/web**

### 3.3 Your Frontend URL
After deployment:
```
https://bolo-debate-web.vercel.app
```

## Troubleshooting

### Backend not starting
- Check logs in Render dashboard
- Ensure DATABASE_URL and REDIS_URL are set
- Run `npx prisma db push` in Render shell

### LiveKit connection issues
- Check LiveKit Cloud dashboard at https://cloud.livekit.io
- Ensure LIVEKIT_URL uses `wss://` (not `ws://`)
- Verify API key and secret are correct

### Frontend API errors
- Check browser console for CORS errors
- Verify API_BASE_URL in build matches Render URL
- Test API: `curl https://bolo-debate-api.onrender.com/health`

## Security Notes

Before going to production:
1. Generate new LiveKit keys: `openssl rand -base64 32`
2. Update `livekit-fly/livekit.yaml` with new keys
3. Update Render env vars with new keys
4. Consider adding rate limiting to API
5. Set up monitoring and alerts
